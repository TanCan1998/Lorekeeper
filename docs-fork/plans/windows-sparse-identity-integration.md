# Windows 签名稀疏身份接入草案

日期：2026-10-19，第114次。**待确认的接入草案，不是ADR或已实现的发布变更。** 证据见[归组研究§8](../research/webview-process-attribution.md#8-第114次签名稀疏身份包原路径正向验证)。

## 已证实与未证实

- 最简宿主可以不搬动EXE，只注册匹配嵌入清单的签名外部位置身份包，就让宿主与全部6个WebView2进程进入同一应用组；不需要浏览器诊断flag。
- 同一EXE、同一路径，注册后三次正向、撤销后的负向成立；不是更换运行库或名称。
- 真实LoreKeeper二进制、NSIS/MSI升级卸载、文件授权/恢复生命周期及macOS仍未验收。生产接入尚未获确认。

## 建议保持的合同

1. 保留NSIS currentUser/SimpChinese与MSI zh-CN，不以完整MSIX替换现有Windows入口；此为建议，待确认。
2. 保持identifier=`com.tancan1998.lorekeeper`、MSI UpgradeCode=`ed3e3199-4ddc-501a-a745-179a185e8dfb`、数据根和项目识别规则不变。
3. 只增加受支持的包身份元数据。作者事实、项目删除确认、外部文件授权、语言/工具协议均不扩权，不新增IPC或数据库迁移。
4. 不使用临时测试证书发行，不在安装器中自动导入信任证书；不关闭签名校验、沙箱、系统策略或开发者模式限制。

## 待确认的实现面

| 面 | 建议 | 当前源码状态 |
|---|---|---|
| 可执行清单 | 嵌入与正式身份包严格匹配的packageName/publisher/applicationId；保留现有DPI、兼容和权限声明 | build.rs目前仅调用tauri_build::build()，未接入身份清单 |
| 身份小包 | AllowExternalContent、mediumIL/win32App，指向安装目录原EXE；稳定包名/发布者，版本规则需明确 | 无产品身份包构建器 |
| 签名 | 使用正式可信代码签名证书或经批准的签名服务，DN必须与清单Publisher一致 | 无本次获授权的生产签名凭据；不得使用/导出既有私钥 |
| 安装 | 完成文件部署后，以对应用户注册已签名身份包，核验包/发布者/路径；失败需显式报错并回滚新增身份，不假报归组修复 | 现有NSIS钩子只覆盖项目清理与本应用注册键清理 |
| 升级/卸载 | 先正常关闭宿主/WebView2，再精确移除旧身份；升级后的版本/路径与签名重新核验；不混入项目删除选择 | 尚未实现身份生命周期钩子 |
| MSI上下文 | 必须解决安装服务与交互用户注册上下文、静默/修复/回滚/多用户语义，不能直接照搬NSIS调用 | 待设计，不擅自新增提权服务或计划任务 |
| 发布门禁 | 缺少可信签名或身份注册/真实归组验证时阻止公开发行，保留旧tag与资产 | 现有Release继续暂停；未改工作流/资产矩阵 |

## 最小实施顺序（确认后再做）

1. 明确稳定包名、正式Publisher/签名来源、NSIS与MSI注册上下文、失败和升级回滚策略，再确认产品清单/安装与CI配置改动范围。
2. 先构建隔离的真实LoreKeeper测试副本。确保启动不激活窗口且数据根/UDF隔离，再测包身份、7个或实际数量的自有PID、共同UIA祖先、默认安全参数与正常关闭。无法后台的交互标记待验收。
3. 先完成一个安装器的注册/失败/卸载/升级闭环，再覆盖另一个；原有默认保留、显式目录+两次确认、静默/被动/升级保护不退化。
4. 覆盖Windows最低支持版本、不同用户/安装位置、路径变化、重复注册/残留、证书续期与发布者一致性；无需/无法获得身份的环境不得宣传为已修复。
5. 补齐真实产品生命周期及macOS对应平台验证，满足发布门禁后才能恢复公开打包/发布。

本轮只记录方案，不改产品构建、安装器、依赖、CI或发布配置；临时证书信任授权不能替代正式签名/发布授权。
