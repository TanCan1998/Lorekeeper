## 确定的布局与身份

| 位置 | 内容 | 约束 |
|---|---|---|
| 用户选择的安装目录 | `lorekeeper.exe`、激活器、`identity/LoreKeeper.msix` 等资源 | 主程序是真实文件，不是空壳或虚拟映射 |
| Windows 管理的包目录 | 小型完整身份启动器与图标 | 不移动包目录、不改ACL、不用链接/VFS伪装 |
| 应用安装记录 | schema、范围、安装目录、包内启动器路径 | 固定应用键；不接受命令行任意目标EXE |
| 构建期望版本 | 既有 MSI 四段版本，经 `LOREKEEPER_IDENTITY_VERSION` 编入激活器 | 与同一配置快照生成清单；不拿旧注册表反推期望版本 |
| 签名预留字段 | 文件/指纹、Publisher、时间戳均null | 不找证书或私钥；signed尚未实现时明确报错 |

默认用户数据仍为 `AI_NOVEL_LOREKEEPER_HOME` / `~/.lorekeeper` 与项目 `.lore/`，云凭据用当前用户DPAPI。全机程序安装不代表共享项目、密钥或用户配置。

## 本轮静态修改与预期

- 构建脚本通过同一 `identityOptions` 生成计划与清单，向 cargo 子进程注入已校验的数字版本。不能用未注入版本的直接 cargo 构建作为生产激活器；不新增依赖或改变主 crate。
- 激活前要求固定包路径、文件存在、版本精确匹配及当前用户注册都就绪；否则最多一次提权刷新，重读记录再次核验，失败不回退到旧身份/无身份。
- 注册后只接受期望版本，确认包内启动器后写回；不强制降级。目录单引号按 PowerShell 字面量转义，文件检测使用 `-LiteralPath`。
- MSI 条件：非完整卸载才刷新；只有显式完整卸载且非升级移除才注销，并在 `RemoveFiles` 前调用。即时执行与 `Return="ignore"` 未改，MSI退出0不代表身份注册成功，也不等于事务回滚完成。
- `--quiet` 传至 MSI 助手、UAC 助手和包内启动器；UAC取消按1223分类，真实取消/策略错误仍待测。新增回归用例未执行。
- MSI 快捷方式与结束动作需另行改接，不能修改生成目录充当持久修复。
