## 确定的布局

| 位置 | 内容 | 约束 |
|---|---|---|
| 用户选择的安装目录 | 真正的lorekeeper.exe与资源 | 不是空壳、快捷方式或虚拟路径；中文/空格外部目录已用最简宿主验证 |
| Windows管理的MSIX目录 | 很小的完整身份包及原生启动器 | 不承诺该小包也能选择任意文件夹；不搬动WindowsApps或修改其ACL |
| 应用专用安装记录 | 安装范围、真实主程序路径、包族/版本与激活标识 | 生产存储和校验尚未实现；不能直接接受命令行传入任意目标EXE |
| 未来签名位置 | 默认为null的证书文件/指纹、Publisher、时间戳字段 | 不读取或自动搜索既有证书；当前signed模式明确报错，不静默忽略 |

这是启动目标的**逻辑映射**，不是目录联接、符号链接、VFS伪装、改进程名称或隐藏成员。MSIX的VFS映射本身不能改变文件真实安装位置。

## 机制与当前实现

- 注册未签名完整小包后，包内启动器具有真实包身份；单纯CreateProcess启动外部EXE并不会传递身份，宿主和浏览器仍返回15700。
- 启动外部主程序时使用公开的 `PROC_THREAD_ATTRIBUTE_DESKTOP_APP_POLICY`，值为 `PROCESS_CREATION_DESKTOP_APP_BREAKAWAY_DISABLE_PROCESS_TREE`（0x02），保留包运行环境。它不是禁用进程树或关闭Chromium沙箱。
- 同一最简主程序、同字节、两个真实外部目录，宿主/浏览器均读回同一包身份，真实Taskmgr共同祖先匹配**8/8个自有PID**：小启动器+主程序+6个WebView2。两个负向仍拆组；无需浏览器诊断flag。
- 新增 `tauri-app/src-tauri/installer/windows-identity.json`、`tauri-app/scripts/windows-identity.mjs` 与同名Node测试。生成器采用既有identifier、MSI四段数字版本、固定未签名专用OID及完整包布局；清单只声明mediumIL/runFullTrust，不嵌入前轮失败的稀疏身份。
- 候选清单仅以实验占位二进制通过真实MakeAppx语法检查；**不是产品包**，未注册。当前生成器未接入tauri.conf、build.rs、NSIS/MSI、发布工作流，`releaseEnabled:false`只是契约中明确的未开放状态，不是已经接线的CI门禁。
- 探针历史清单还有unvirtualizedResources能力；本次候选清单没有加入该额外能力。清单结构合法不代表最小能力候选的文件/注册表虚拟化、真实归组与产品行为已通过；如需扩大能力或修改权限，仍须先确认。
- x64本机机制及清单检查已完成；模板允许ARM64生成不代表ARM64真机通过。未签名部署候选最低Windows为10.0.19041.0，不据此声称现有安装器已实现系统版本门禁。

## 后续签名不是只填PFX

保留字段均为null。unsigned模式填入任何签名值会报错；signed模式当前也报错，避免“填了但没签”的假成功。不保存密码/私钥，不自动读环境变量或证书库。未来可信签名将改变Publisher及包族，须设计旧注册/激活入口迁移，不能只修改证书位置便宣告兼容。无需现在购买、申请或开户。
