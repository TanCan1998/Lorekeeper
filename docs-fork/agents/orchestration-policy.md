# 项目交接与编排规范

本规范由用户授权的流程优化整理。领域约束仍见根 AGENTS.md。普通编辑任务不必全文加载；派发、恢复、复验和交接时读取对应章节。

## 信息职责

| 文件 | 维护内容 | 写入者 |
|---|---|---|
| docs-fork/handoffs/CURRENT.md | 当前入口、最近冻结快照、状态与规范链接 | 编排者 |
| .pi/tmp/pipeline-state.md | 活动任务、runId、文件占用、未解除阻塞、下一步 | 编排者单写 |
| docs-fork/handoffs/日期快照 | 已验证进度与交接证据；旧日期冻结 | 编排者 |
| 频道清单 | 契约及映射；口径变化时更新 | 编排者 |
| README 与 todo | 展示视图，不作为第二份任务账本 | 从上述事实源更新 |

授权和方法不放进运行状态；历史任务不滚动复制。旧记录移到本机历史文件或引用已有快照。原始记录保留，当前视图仅列未解除事项。

## 现有授权与资源约束

以下沿用原状态文件中的用户授权，不能由模型自行扩大：

## 用户委托（常驻全权委托模式，2026-10-11 授予，本会话确认仍有效）
- 模型：双通道轮换 —— `lorekeeper-task`（tokendance/ling-3.1-flash）与 `lorekeeper-task-b`（tokendance-1/ling-3.1-flash）逐派交替，**派发不传 model 参数**（模型固化在 `.pi/agents/` 两个 agent 的 frontmatter）
- 已委托：波次选择、子代理派发与模型轮换、独立复验、波次拆分与提交、临时产物清理、**并行子代理数量与并行度**（2026-10-11 用户新规：可并行任务——写面不重叠且无依赖——尽量并行，编排者自主决定并行数，无需逐波请示；依赖链仍串行。**并发上限：同时在飞子代理 ≤ 4 个，双通道各 ≤ 2**（2026-10-12 设定 ≤2，同日用户调高一倍至 ≤4）——一池 503/超时时另一池仍可工作，避免同池多 run 连锁失败；重派替换失败槽位，不叠加占槽。**日常保持 ≤ 2（双通道各 ≤ 1）**；仅当波次内任务无依赖、写面不重叠、且复验已跟上时，临时用到 ≤ 4）
- 子代理命名（2026-10-12 用户新规，同日终修订）：**派发前动态创建批次 agent**——`subagent({action:"create", options:{config:{name:"<批次名/波次名>-<角色>", scope:"project", model:<按当派轮换通道：tokendance/ling-3.1-flash 或 tokendance-1/ling-3.1-flash>, tools:"read, edit, write, bash, contact_supervisor", systemPrompt:<复用 lorekeeper-task body>, systemPromptMode:"replace", thinking:"medium", inheritProjectContext:false, inheritGlobalContext:false, inheritSkills:false, description:"<批次简述>"}}})`——运行时注册，绕过 `.pi/agents/` 启动扫描缓存（已实测：完成通知 / PiDeck 显示批次名）；派发 `agent:"<批次名>-<角色>"`；收口后 `subagent({action:"delete", agent:"<批次名>-<角色>"})` 清理。配套：① task 文本以「<批次名>-<角色>：」开头（显示名 = `agent: <task 前 60 字符>`，源码 `child-session-name.js` 写死）；② `options.sessionDir: ".pi/tmp/subagents/<批次名>-<角色>"`（相对仓库根，session 目录以批次名命名）。**常驻双通道不变**：lorekeeper-task / lorekeeper-task-b 仍是模型通道载体；Temp 下 run 目录 = runId 不可改

- 推送授权（2026-10-13 用户新规，取代逐波确认）：**普通 git push 无需逐波确认**——复验通过 + 提交后编排者自主推送；**force-push 改写已推送历史仍须用户确认**（如 rebase reword）
- ask_question 保留：红线项（新依赖 / schema 变更 / CI 配置等 AGENTS.md ⚠️ Ask first 项）

## 派发与文件占用

- 先读取活动占用表，完整列出目标文件（包含 owner、模块导出及测试等隐式写面）。同文件或有编译/数据依赖的任务串行；只读 scout 可前置。
- 每个任务有稳定 taskId；每次重派有独立 attempt 和 runId。失败占用释放后才替换槽位，不叠加重派。
- 正常并发不超过 2，两个通道各 1；独立任务且复验跟得上才提高至 4、每通道至多 2。模型交替、动态批次 agent 创建与删除沿用现有授权。
- 使用 dispatch-template.md 的自包含简报。小任务通常控制在 3 个写面文件内；确需更多时由编排者显式裁定，禁止子代理自行扩面。
- worker 开工先报告预计时长、额外读取范围、冲突检查，等待编排者裁决；目标文件有未提交改动即停并上报。禁止 git add/commit 和修改全局状态文件。
- 单 worker 最多 30 分钟，通常先用 20 分钟任务预算；checkpointBeforeDeadlineMs=120000。预算写清研究、实现和自检分配。API 预算参数只用当前扩展实际支持的名称。
- 每次写前检查分支；改用新鲜 edit anchor，大区段一次替换，修改一文件即做相关增量检查。发现额外写面时停止，报告 CONFLICT-NEEDS-REASSIGN。
- 异步完成通知驱动状态变化，不常态轮询。仅异常、恢复或明确需要中途监督时查询 status；503/零进度失败先核查落盘，再替换到另一通道。

## 状态与事件更新

主流程：待派发 → 执行中 → 待复验 → 已验证 → 已提交。阻塞/失败为独立状态，保留恢复入口。子代理成功返回仅进入待复验；进度数字只纳入已验证成果。

| 事件 | 必须写入的变化 |
|---|---|
| 派发 | taskId、attempt、runId、agent/通道、baseHead、写面、依赖、预算 |
| 完成 | 待复验、结果/原始输出路径、执行槽位释放；写面继续保留至复验或交付 |
| 失败/阻塞 | 原因、落盘范围、分支状态、后续裁决；保留历史尝试 |
| 复验 | 命令、范围、exit、verifiedAt、验证代码版本/工作区标识、证据路径 |
| 提交 | commit、已提交；更新活动视图与相关进度展示 |
| 交接 | CURRENT 指针与短摘要；未完成事项、阻塞及下一步 |

仅编排者写状态。更新前重新读取并核对版本；发现文件被其他会话改动时先合并，禁止用旧上下文覆盖。优先写临时文件后原子替换。每次只更新事件涉及的字段，不累加工作日志。

## 独立复验与证据

编排者必须独立执行交付任务的验收命令，检查实际写面；子代理自述不能代替证据。验收范围按改动及依赖决定。无代码变化的状态/文档更新不重复运行整个项目测试。

Rust 验证频率统一遵循 [开发指南 §7](pi-development.md#7-测试约定)：日常切片跑相关定向测试，阶段/累计/风险触发才跑全量；提交或推送本身不触发重复全量。复验记录区分本轮范围与最近全量基线，累计数维护在 pipeline；此约定不恢复当前禁止派发代理的规则。

多任务可共用一次相同版本的独立验收，记录覆盖的 taskId。长输出落到证据文件，摘要只放关键行、退出码及链接；不全文嵌入交接。

HEAD 单独不能标识脏工作区：记录 HEAD + 相关 diff/文件摘要，提交后核对对应 commit。影响范围变化使相关验收待更新；未变化的指标可保留，但必须标明原验证时间和版本，不能冒充本轮实测。重跑后才更新对应数字。

## 收口与交接

1. 收口时停止新派发；保留正在运行的任务。等待自然完成或终止运行由用户已有授权/明确裁决决定，不能默认 stop。
2. 核查 run 实际状态与工作区；执行独立复验。提交/普通推送沿用授权，force-push 仍需确认。
3. 持久证据与结果摘要留下后再清理已完成运行的临时产物。先核对确切路径和工作区范围，不删除在飞或唯一证据。
4. 更新活动状态；将已结束事项移到快照或本机历史。冻结历史快照不改，不在新快照重复展开已解除阻塞。
5. 新会话先读 CURRENT 和短状态；仅在需要领域细节、任务证据或恢复异常时读取相关快照章节、简报和历史记录。

## 进度展示

最新已验证快照指标为发布进度事实源；当前工作进度取活动状态。README/todo 展示应从两者更新，不独立编造数值。普通状态变化只更新活动摘要，不触发全量测试；频道收口或口径变化才更新对应指标。

本次实现为文档流程和模板统一；没有新增自动生成脚本。自动生成可在后续基于稳定字段实现，当前仍由编排者按单一来源同步展示。
