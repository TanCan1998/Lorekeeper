## 本次调整

- 合并上游 1.3.1 基线；本 fork 仍为设定司 / LoreKeeper，不跟随上游改名。未逐项平移的新修复仍留在 Electron 基线，不能把上游版本号当成 Tauri 的功能验收。
- 新增本机写作 Skill 文件/文件夹导入：原生选择后检查，再以窗口绑定、限时、一次性候选确认安装；正文引用的文本随包保存。列表与生成快照共同校验安装清单和 SHA256，损坏后禁止用于生成，不执行脚本或工具。
- Windows MSI 快捷方式及安装后启动统一经过身份激活器，按当前用户按需注册独立身份；不改变项目数据目录。

- 接入原创“司”字单星图标，统一可见名称为 LoreKeeper / 设定司，保留原应用标识、数据目录及 MSI 升级身份。
- Windows EXE（NSIS）安装、卸载使用简体中文；卸载默认保留项目。可勾选“清理所选项目”，随后必须手动选择目录、两次确认，才删除该项目目录及全部文件。
- Windows MSI 使用 zh-CN 与递增数字版本；静默/被动/升级卸载默认保留项目。MSI 卸载不弹自定义清理对话框，可在卸载前执行 lorekeeper.exe --cleanup-project。
- 清理入口不扫盘、不读最近项目列表，不删除全局配置、Vela 数据或共享 WebView2；拒绝系统/程序目录、链接、嵌套项目及含其他数据根的目录。操作前请退出全部实例并备份。
- EXE 卸载将本应用安装位置/语言注册键的清理与“保留项目”选项解耦；系统管理的 MSI 注册信息由 Windows Installer 清理。
- macOS 保持拖拽安装/卸载，默认保留项目；应用包内附中文说明。可在卸载前执行 open -n -W -a LoreKeeper --args --cleanup-project，进入同样的中文清理流程。

## 已知限制

- Windows 已接入稀疏包身份与激活器；前轮本机 MSI 已验证安装、修复、身份重注册、快捷方式启动和卸载。不能以这些历史证据代替本次四个新包的原生验收；所有 WebView2 子进程的任务管理器归组、最低 Windows 与多用户 UAC 仍未完整认证。
- macOS WebKit 宿主归属与活动监视器显示仍待真机验证；没有承诺隐藏系统子进程。
- 本次新安装包的真实安装/升级/卸载、Skill 原生文件选择器、项目删除与注册表清理仍待原生验收。自动测试只使用合成材料；静态与模拟测试不等同于本次产物真实卸载通过。
- Skill 清单使用本 fork 的 `.lorekeeper-bundle.json`，与 Electron 用户库隔离；安装中途失败保留损坏目录，不自动递归删除，需检查后清理或卸载重试。
- Windows 未证书签名；macOS 仅 ad-hoc 签名，未开发者签名、未公证。
- 真实模型、MCP 服务、业务云及长期写作质量仍未认证。建议使用可丢弃项目和本地备份体验，不用于唯一正文副本。

发布过程核验三平台同一源码 SHA、四个安装包的大小与 SHA256，附清单与校验文件；摘要不是代码签名或功能认证。
