# Lorekeeper 旧版副本导入：核查结论与范围纠正

## 产品事实

**目前没有已确认发布成功、可作为导入来源的旧版 Lorekeeper。**

此前将源码中的旧结构兼容逻辑和开发过程中的 schema 变更，
延伸为“存在旧版 Lorekeeper 项目需要迁移”，缺少实际产品与数据来源依据。
用户已指出这一前提错误。撤回隔离副本升级及临时来源 UUID 的实施/确认请求，
不为并不存在的输入格式继续设计迁移链路。

## 源码事实不等于产品旧版

- 上游 `project:import-legacy-copy` 面向 Electron 旧项目，读取 `.vela/vela.db` 与 LanceDB。
- Tauri 源码存在无清单项目指纹、project_core 补列、角色名单兼容与租约围栏逻辑。
- Git 记录存在 m01/m02/m03/m05 等开发期结构变化。

以上只能证明代码包含兼容路径，不能证明存在已发布的旧版 Lorekeeper，
也不能据此承诺支持某种真实旧库。此次未扫描用户项目或小说数据。

## 当前处理

1. 不读取 Electron 的 `.vela` / LanceDB，维持已确定的双栈隔离。
2. 暂缓 `project:import-legacy-copy`；保留上游契约，不注册不可用占位命令凑覆盖。
3. 不运行旧库升级、不分配所谓临时来源身份、不修改源项目。
4. 将来确有真实输入格式和导入需求时，再明确来源版本、样本、无损要求与授权范围。
5. 当前继续推进实际需要的云备份链路；DPAPI 凭据基础层已单独完成。
