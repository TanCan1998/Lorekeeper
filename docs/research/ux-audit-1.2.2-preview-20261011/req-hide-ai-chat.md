# 需求：隐藏 AI 聊天入口，保留工作流显示

- 日期：2026-10-11。版本基线：1.2.2-Preview，`origin/master` `6f269a92`。
- 状态：需求已和用户对齐，尚未实施。
- 关联：同目录 `README.md`（UX-01～UX-07）、`design-redundancy.md`（UX-08～UX-26，其中 UX-10 是“两块 AI 面板”）。

## 背景

本产品是用流程控制小说写作的 harness：配置 → 架构 → 蓝图 → 草稿 → 审稿 → 修稿 → 定稿，每一步都由页面按钮触发工作流。
主界面右侧默认显示 AI 聊天面板（“AI 写作助手”），会让用户以为这是一个靠和 AI 对话来控制的软件，误读了产品的定位。

## 已对齐的决定

| 事项 | 决定 |
|---|---|
| 移除程度 | **只隐藏界面**。用户在任何位置都看不到聊天；聊天相关代码（`components/panels/agent/`、`services/agent/`、`stores/agent-store.ts`）保留，不删除。 |
| 工作流显示 | **全部保留，位置不变**：右侧“AI 输出”、底部“任务”面板、状态栏进度提示。是否合并这几处，留到前端整体重新设计时再定。 |
| 历史数据 | **数据保留，不再显示**。磁盘上的旧对话和 Agent 恢复记录不删除、不迁移；界面上不再列出它们。 |
| 聊天独有能力 | **接受随之消失**：自由问答、助手文件产物、用 `/` 调用写作 Skill、对话里的修改提案。生成蓝图、填充配置、启动创作、检索知识库、绑定 Skill 都已有页面按钮。 |

## 范围：需要隐藏的可见入口

| 入口 | 位置 |
|---|---|
| 右侧工具栏的 AI Agent 按钮（机器人图标） | `src/components/layout/RightToolWindowBar.tsx:48-63` |
| 右侧面板默认显示聊天视图 | `src/stores/layout-store.ts:98`（`rightView: 'agent'`）、`src/App.tsx:273` |
| “AI 输出”里的“切换回 Agent”按钮 | `src/components/panels/AIOutputPanel.tsx:253` |
| “AI 输出”里的 Agent 中断恢复列表，以及点击“恢复”后跳回聊天的操作 | `src/components/panels/AIOutputPanel.tsx:392-405` |

聊天面板内部的入口（新建对话、历史对话、MCP 服务器、技能列表、`/` 命令、`@` 引用）随面板一起不可见。MCP 服务器只能从聊天面板管理，因此它的管理界面也一起不可见。

## 不在范围内

- 删除聊天代码，或取代 ADR-0008（“AI 助手动作必须通过项目事实与工作流 seam”）。代码还在，ADR 继续成立；以后真要删除代码时，再写新的 ADR 取代它。
- 合并或重新排布“AI 输出”、底部“任务”和状态栏，以及给“AI 输出”改名。这些都归入前端重新设计。
- 产品名“AI 小说作家”和其他文案里的“AI”字样。

## 验收条件

1. 不论是首次启动、新建项目还是打开已有项目，中文和英文界面里都看不到任何聊天入口（上表 4 项）。
2. 打开右侧面板时，显示的是“AI 输出”。
3. 工作流启动时，照常自动打开“AI 输出”；底部“任务”面板和状态栏进度提示照常显示，点击后的行为和现在一样。
4. 页面上已有的生成和工作流按钮全部照常工作：AI 填充配置、AI 生成架构、AI 生成蓝图、写作此章、批量创作、AI 审稿、AI 修稿、定稿、AI 提取角色卡。
5. 旧项目里已有的对话和 Agent 恢复数据仍在磁盘上，没有被删除或改写；打开这类项目不报错。

## 实施时需要注意

- 只隐藏界面时，`App.tsx` 启动阶段仍会初始化 MCP（`useMCPStore.init()`）。如果用户以前配置过 MCP 服务器，它们会在界面不可见的情况下继续连接。实施时要确认是否接受这种情况；如果不接受，在共同入口停掉初始化，不要在多处分别拦截。
- 现有测试如果断言了聊天按钮或聊天面板可见，需要随本需求一起更新，并在 PR 里说明这是需求变更，不是放宽验收。
